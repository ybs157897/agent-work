# 需求处理统一到现有 Chat 和 Run

Status: implemented

## 决策与理由

原件以核验后的文件路径交给运行时，分析、问答、确认和发布沿现有 Chat、Run、ModuleRunner 与 Task 推进。旧 stateless 需求模型接口没有运行记录和同一来源校验边界，删除其 provider、HTTP/OpenAPI 及死客户端，避免存在两条可调用的处理路径。

历史浏览器草案属于需保留的内容。保留按 Workspace 的只读发现和显式文字恢复，显示旧标题、projectKey 来源以及当前目录规则；恢复不会更改全局代码根、执行旧发布或提升为产品批准。

新空间一次性继承普通 Agent 及内置服务可配置的模型设置，创建独立身份。系统提示、策略和模板仍由当前应用保护；不复制任何业务记录和运行状态。模型注册表与凭据引用继续作为应用配置共享。

## 放弃了什么

不保留旧 HTTP 模型接口作兼容层，不把旧项目标识重新绑定成页面级目录，也不通过重写历史确认消除变化。旧 mixed tree 和实际验收失败证据保留，当前主流程只接受受校验的新版本与明确的产品回填。
