日期：2026-09-07

## 当前产品方案 V2（2026-09-08）

用户最新确认：知识库 Tab 只用于看内容，不用于录入或管理。知识管理员是系统内置 Agent，和其他 Agent 使用同一聊天入口、同一正文展示风格；产品、开发或其他团队成员在对话中完成需求后，由 Agent 主动调用知识管理员记录和整理知识。

知识库页面的唯一跨页动作是“与知识管理员对话”，目标为 /chat?agent=智能体列表中 kind=knowledge_librarian 的内置 Agent ID。页面不写死或猜测管理员 ID；智能体列表读取失败或内置 Agent 缺失时，继续提供只读浏览并明确说明入口暂不可用。

知识库日常页面只承担四件事：

1. 搜索已发布知识的标题、摘要、标签和别名。
2. 按“产品需求、团队约定、功能说明、业务规则、决策记录、事实、观察与经验”浏览。
3. 打开正文，查看来源证据、当前有效关联和版本。
4. 在空态或需要新增知识时，引导用户与团队成员聊需求，由成员主动交给管理员。

页面不提供人类录入资料、发起调查、提交候选、启动整理、发布、废止或管理员配置按钮；这些是 Agent 和控制面的职责。页面也不把 Agent ID、知识 ID、版本号、scope 或关系 kind 当作主标题。

最小读取接口是：智能体列表 GET、知识配置 GET（可用状态）、effective 知识列表 GET（可选 kind）、条目详情 GET、版本列表/详情 GET、正反向关系 GET。搜索和语义分类只改变读取视图，不创建 Submission、KnowledgeJob 或任何写操作。正文继续复用 AgentOutput，保持与其他 Agent 聊天正文同源。

语义分类至少包含“产品需求”（kind=requirement）、“团队约定”（kind=agreement）、“功能说明”、“业务规则”、“决策记录”、“事实”和“观察与经验”。列表使用 next_cursor 继续读取；当当前页没有命中搜索词但仍有 next_cursor 时，页面必须显示“已加载内容暂未匹配”和“继续加载知识”，不能提前宣称全库没有匹配。

空态文案固定为：“这里还没有已发布知识。与团队成员聊需求，成员会交给管理员记录。”可用时提供“与知识管理员对话”入口；没有可用 ID 时改为“知识管理员入口正在准备”，不渲染坏链接。

### 当前验收标准

- 打开 /knowledge 后，首要内容是 effective 知识、搜索框和语义分类。
- 页面无材料、调查、整理、发布、废止和配置写操作。
- 已发布知识详情展示 AgentOutput 正文、来源、关系和版本；稳定 ID 仅在详情的折叠技术信息中出现。
- 唯一跨页入口使用智能体列表中内置管理员的真实 ID，且进入普通 /chat 页面。
- 搜索、分类、打开详情、切换版本和读取关系均为只读；失败时显示对应区域的重试。
- 空态明确告诉小白下一步去与团队成员聊需求，不要求用户自己整理知识结构。
