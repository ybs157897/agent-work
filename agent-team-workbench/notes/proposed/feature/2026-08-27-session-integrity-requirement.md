# 会话信息完整性治理：需求存档（起章确认版）

Status: proposed

## 决策与理由

2026-08-27 经需求蒸馏（起章）并与用户逐条确认，本需求以用户拍板版本存档，作为后续开发的唯一依据。

**一句话**：给四层架构（web / 适配端 / harness+agent loop / 模型）里的会话立一套可靠的生命周期管理；验收公理由用户给出——**模型无状态，只关心请求过来的信息完整性**。由此推出不变量：任何一层异常、任何换底（codex↔kimi）、任何轮换，工作台都必须能为模型重建一个信息完整的请求。

**用户拍板的三项决策**：

1. 范围 = **信息完整性优先**：先补最违反公理的两处——回放保真度（历史回放只带「指令+最终回复」，丢工具轨迹/中途输入）与 35% 预算悬崖（超预算从全量直接跳崖到 8×400 规则摘要）。
2. 节奏 = **先落设计 note 定口径**，确认后再动代码（改动集中在 `agent-team-workbench/internal/application/conversation.go` / `sessions.go` 等核心文件）。
3. web 会话生命周期观测面 = **这次一起升级**（现状只有 `session.decision` / `session.compacted` 两条 system 行）。

**明确不做（本轮）**：锚点状态机显式化（骨架项，让位于信息完整性）、provider 侧上下文对账、LLM 滚动摘要——取舍与复活条件见设计 note。

**调研基线**（本会话确认的事实，开发前提）：会话全量台账只增不删；换底走 fresh+历史回放、三层防护保证 `codex://` 不喂给 kimi；`session_unknown` 自愈写墓碑不静默降级；失败无通用自动重试。
