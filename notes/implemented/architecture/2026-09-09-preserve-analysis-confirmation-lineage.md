# 保留分析对象与产品确认谱系

Status: implemented

## 决策与理由

变更分析可以显式列出未变事项/问题 ID，由服务端从该 Run 冻结的 base revision 展开原对象，再运行完整严格校验。产品回填保存在独立不可变记录，不由模型复写，也不拼进事项文本。新 revision、确认有效性与回答谱系在同一事务提交。

真实 AI 曾将“产品已确认、保持不变”添加到 JDK 事项文字和来源里，导致指纹变化、无关确认重开。精确保留避免这种文本改写；保留问题若引用变化事项，其依赖指纹仍变化，旧回答不会继承。旧 conversation 来源需保留于已授权目录，不能随最新聊天历史裁剪丢失。

## 放弃了什么

不按相同 item ID 自动判定未变，也不用模糊文字相似度继承批准。无法证明来源和对象一致时保留历史并要求复核。模型省略旧事项不能默认为保留，preserve 不能绕过当前来源授权、摘要核对和版本限制。

## 复活条件

若后续协议提供可靠的结构化语义变更证明，可评估更细的字段级继承；仍须保留当前不可变历史和服务端来源校验边界。
