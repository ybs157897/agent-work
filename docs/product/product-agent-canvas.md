# 产品 Agent 知识画布

状态：用户于 2026-09-08 确认文档/全景交互；实现与验收结果见[验收记录](product-agent-canvas-acceptance.md)。

## 工作区

产品 Agent 默认进入“中间知识画布、右侧对话”的工作区，文档是默认视图；全景展示同一批知识及其有效关系。产品默认来自显式 `role=pm` 配置（当前 Nova），不从名称、提示词或技能文案猜身份。普通 Agent 也可用明确的“知识画布”开关进入；开关偏好按工作区和稳定 Agent ID 隔离，不改变后端权限。

沿用现有 `/chat?agent=<id>` 会话路由、Run、消息流、发送队列和错误恢复。工作台主侧栏保持显示；画布工作区内的会话导航可主动展开，较窄窗口通过“文档/对话”切换保证正文和输入区可用，不压缩成不可读的三栏。

## 文档与知识归属

目录查询 `status=effective&owner_agent_id=<当前 Agent>`，筛选在服务端执行并参与搜索与分页。Owner/Admin 可读取该 Agent 的私有视角；其他角色只读其共享知识。读取失败显示错误和重试，不显示为空库。没有知识时保留对话入口并说明需要通过与 Agent 讨论沉淀内容。

正文复用 `AgentOutput`，展示真实标题、正文、目录、来源、关系和版本。全景节点只有标题与摘要，点击进入完整文档；关系只来自服务端且两端都在当前可读集合内。拖动、缩放和布局属于展示状态，不写入知识正文或发布关系。图组件按需加载，关系读取有界并限制并发。

读者可显式引用选中段落。引用保存工作区、Agent、知识条目、确切版本、标题及选区；右侧明确展示并允许移除。选中本身不发送。发送时把版本引用和摘录作为 `atw-knowledge-reference-v1` 明确标记的数据尾段，与问题一起交给现有 Chat，重试/排队使用同一份内容。发送后的用户气泡显示问题和可展开的版本引用卡；只有合法的完整数据尾段才会折叠，普通文字或不完整格式仍原样展示。更换正文不会悄悄替换已选引用，切换 Agent/工作区/会话不会串入旧引用。

请求失败且尚未进入发送队列时，恢复问题和引用卡；如果用户在等待期间选中了新的引用，保留新引用并把旧问题与引用内容恢复到草稿供核对。发送期间主动切换工作区仍沿用原 Chat 的失效响应策略，不新增跨工作区草稿持久化承诺。

知识写入仍通过 Agent 和知识管理员。读取刷新、对话运行完成后检查均以服务端结果为准；出现新版提供提示，阅读历史版本时不强行跳转。当前没有知识发布 SSE 协议，因此不能宣称所有外部后台发布都会即时推送；用户可以手动刷新。

## 统一风格

当前设计事实源为 [DESIGN.md](../../agent-team-workbench/web/DESIGN.md) 2.0：统一 LanguageGUI 明暗主题、中性表面、蓝色操作强调、无衬线正文。画布使用共享语义 token 和工作台主题 store；React Flow 的默认样式也映射到这些 token。交互草图仅作为布局参考，其纸色、朱砂色和装饰不得移植。

## 验收

- 点击产品 Agent 后默认呈现画布与真实对话；关闭/重开、刷新、切换会话不丢已发送记录。
- 真实 owner 查询和全文搜索分页排除其他 Agent；私有知识仍受权限与工作区限制。
- 文档/全景切换、点节点阅读全文、版本与来源、引用到输入区和真实发送形成闭环。
- 引用版本固定；发送失败可重试，快速切换 Agent/文档不接收迟到数据。
- 新版提示来自真实读取结果；全景拖拽不产生知识写操作。
- 明暗两种模式与工作台一致；桌面与窄窗口、固定主侧栏、portal 弹层、键盘焦点和低高度输入区均经浏览器检查。
- 后端触面测试及 race、Go build/vet；前端 `tsc -b`、测试、lint、build 和 token 门禁通过。
