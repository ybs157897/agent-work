## 已确认的要求

1. **一个工作空间对应一个项目目录；选择唯一，并且全局使用。** 全应用只有一个工作空间切换入口。对话、任务、附件、草案、确认记录、代码上下文和 Agent 业务知识都跟随它。新建空间从独立内容开始；切到已有空间加载它自己的内容；切回来恢复旧内容，不清空或复制其他空间。
2. **Agent 知识库按工作空间多一层级。** 逻辑归属为“工作空间 → Agent → 该 Agent 的知识”。不同空间可以处理不同性质的内容。同一名称或角色的 Agent 在不同空间的知识不得混用；已有空间内共享知识仍只在该空间的可见范围内使用。
3. **文档驱动、分单元处理、验收后勾完成。** 每个单元分别写目标、范围、输入输出、依赖、验收和交接记录。一次集中处理一个单元；无依赖且文件不重叠时才并行。
4. **AI 负责读取和整理材料。** 原附件交给 AI，AI 结合对话、代码和知识读取、理解、分析；工作台负责材料保存、访问范围和来源记录。本机 Runtime 使用服务端核验后的原文件路径，由 Agent 自行读取；不依赖原生附件上传协议。上传不等于 AI 已读，不用固定后端摘要替代 AI 的理解过程。
5. **需求处理在现有 Agent 对话中完成，开发使用，一次一问。** 需求不具体、异常遗漏、材料冲突和持续变更都是目标场景。系统给出来源、影响和建议，开发与产品沟通后逐项回填；未答问题不自动确认。
6. **web-idea 用作验收范本。** IntelliJ Community 是 Java 能力参考。参考项目能力不等于已确认交付范围，不据此开始移植全部 Java 功能。

7. **新空间复用当前 Agent 配置。** 一次性复制角色、提示词、技能、模型及必要运行配置，创建独立实例；不复制聊天、任务、知识、会话、运行态或自动运行记录。后续配置独立维护。

## 统一边界

- 唯一当前工作空间来自全局入口；各页读取同一状态，不再维护页面自己的工作空间选择。
- 一个经核验的本机项目目录是该空间固定项目根；分支变化属于代码版本变化，不再另设页面级项目或 checkout 选择。
- 工作空间是业务内容边界，Agent 是空间内知识归属与访问范围。不能只在界面过滤，查询、读取、写入、检索缓存和 AI 工具调用都必须遵守同一归属。
- 切换只改变当前查看/操作的空间；正在运行的任务保持原有空间归属，结果不能落入新空间。运行状态仍由现有控制面负责。
- 本 MD 管理开发进度，不替代产品里的 SQLite、Task 或 Run 状态。
- “单元独立”指责任和修改边界明确、可单独验证；必要依赖以输入输出合同表达，不承诺功能间没有依赖。

## 每个单元的执行规则

1. 开工前填写该单元的 owner、分支/worktree、目标文件和验收步骤。读取总清单、当前单元以及直接依赖的“交付合同”，不重读全部历史。
2. 先核对已有实现再动手。不得因为文件存在就称功能完成，也不得重造现有的工作空间字段、知识体系或执行状态机。
3. 一个单元一个修改范围。共享文件由一个 owner 修改；其他单元先提出合同变更，不直接覆盖。依赖未交付时保持待开始或阻塞，不越界补写别人的功能。
4. 新实现使用独立任务分支/worktree。现有未提交混合改动先逐项归属并保留，再决定移入哪个单元，不整体删除、整体提交或让多个单元同时修改同一份状态。
5. 只有“实现接通 + 触面检查通过 + 真实行为验收有证据”全部满足，才把单元和总清单同步改为 `[x] 已完成`。协议模拟、样本自检、类型检查或编译通过分别注明，不能互相替代。
6. 暂停/交接前更新该单元的当前位置、已完成项、未决项和下一步。记录短结论与证据链接，不粘贴长日志、凭据或整段聊天。
7. 总清单是单元完成状态的汇总，单元文件是验收细节依据；两者同轮更新，出现不一致时按未完成处理。
8. 提交、合并、推送继续遵循仓库和用户的授权范围。用户已明确授权实施本计划；不另行询问是否开始。
