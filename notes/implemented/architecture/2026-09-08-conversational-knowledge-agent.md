# 内置知识管理员与对话录入

Status: implemented

## 决策与理由

用户明确纠正：知识库管理员属于内置 Agent，聊天方式和正文风格与其他 Agent 相同；知识库标签页只用于看内容；录入由各 Agent 调用管理员完成，例如用户与产品讨论需求后，产品 Agent 调用管理员录入。这些是本轮已明确的要求，不再沿用上一轮人工知识操作台的产品定义。

系统提供稳定的 `knowledge_librarian` 身份，固定职责与提示词，仅开放运行时和模型配置。它进入既有 `/chat`、会话、Run 与 `AgentOutput` 流程；`task_coordinator` 和未知系统身份继续受保护，不进入普通对话。内部 curation Job 是管理员执行结构化整理的工具，不替代用户看到的统一聊天界面。

普通 Agent 通过当前 Run 授权的录入工具向管理员提交需要沉淀的自然语言内容。管理员负责拆分、去重、关系、来源和版本，返回真实入库结果；权限和版本仍由既有控制面校验。已确认的需求能够在没有知识库人工发布按钮的情况下闭合；需要确认的信息回到对话，不能用一句“已记住”替代数据库结果。

## 放弃了什么

- 删除知识库页面的交资料、调查、整理、发布操作台，不把它们简单搬入折叠区。
- 不再由用户挑任意普通 Agent 充当管理员，不按 `role=librarian` 字符串冒认内置身份。
- 不新增专属聊天页或正文渲染器，不把结构化 JSON 作业结果当作管理员面向用户的主要回复。
- 保留上一轮真实修复的空技能、失败原文恢复、目录重连和 Kimi 后台生命周期，产品方向错误不要求丢弃独立有效的修复。

## 验收场景

1. 新工作区提供唯一内置知识库管理员，可在统一聊天入口选择；模型可配置，固定身份不可编辑。
2. 用户与产品 Agent 正常讨论并确认一段需求，产品 Agent 真实调用管理员，管理员整理并完成受控入库。
3. 用户打开知识库即可读到该内容、来源和关联；页面没有录入、调查、整理或发布表单。
4. 用户直接与管理员聊天，回复由同一个 AgentOutput 渲染，并能真实检索/记录知识。
5. 原有知识、会话及运行引用保留；跨工作区、冒充来源、固定身份修改均被拒绝。

## 本机知识工具传输

真实验收发现：Codex 默认文件沙箱阻止 Shell 客户端访问本地 HTTP 服务，会要求用户审批终端命令。为保持自动录入体验，Codex 使用应用注册的固定 `atw_knowledge` 原生工具，应用在宿主端处理 ask/read/record；权限仍绑定当前 Run 的 capability，参数不能选择工作区、Agent、URL 或凭据。不自动批准 Shell，也不放宽文件或网络沙箱。

工具定义在 thread/start 注册，由 Codex 随会话持久化；resume 使用已有定义。稳定工具协议版本进入既有配置指纹，旧会话按 config_drift 路径轮换并回放历史；每轮 token 和访问文件不进入配置指纹，不引入持续轮换。

Kimi 等现有支持 Shell 的本机运行时继续用同一 Run-bound API 客户端；CLI 支持参数放在正文前后，help 不发起请求。远程 Host 不分发本机 capability。

验证：普通产品对话自动录入生效 v1、同会话 resume 原生查询、内置管理员直接查询均经真实 GLM 与 SQLite/UI 取证。前端 903 测试、后端触面 race、迁移、build/vet、gofmt 和 diff 检查通过。详细证据见 `docs/product/conversational-knowledge-acceptance.md`。
