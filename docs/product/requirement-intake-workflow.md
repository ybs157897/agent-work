# 开发需求分析与确认闭环

> 2026-09-09：功能开发已暂停。当前统一边界、拆分单元与进度以[执行总清单](workspace-ai-workbench/README.md)为准；本文件只保留主流程说明。

## 目标与已确认范围

内部开发在需求不完整、材料分散且持续变化时，从唯一全局入口选择工作空间，在该空间关联项目资源，把对话、项目源码、该空间的 Agent 知识及 Word/PPT/Markdown 附件交给 AI。AI 读取材料并整理需求、正常与异常场景、冲突及影响，提出有来源的建议，开发与产品沟通后逐项回填确认。界面一次展示一个当前问题，未答问题保持待定。

这是用户已确认并要求开始的工作范围，项目选择只是入口。web-idea 是验证目标，IntelliJ Community 是 Java 能力参考；不据此授权移植全部 IDE 或开启源码写入。

## 数据与行为合同

- 一个需求分析记录属于全局当前 Workspace；项目目录/checkout 是该空间内的关联资源，不是页面自己的第二套工作空间。服务端保存资料快照、分析版本和确认历史；不创建另一套 Task、Run 或调度器。
- 工作台保存原附件及来源元数据，由 AI 主动读取和分析；上传动作不等于已读，不先用固定后端规则提炼或整理附件内容。文件格式读取工具只承担 AI 请求的内容访问，不替代 AI 理解材料。
- 所有来源保留类型、名称、定位、内容版本及 AI 读取状态。代码只能从已核验 checkout 中按有界范围读取；知识只取当前调用者可访问的确定版本。不执行附件宏或链接，不把图片/失败部分伪称已读。
- 模型输出区分需求、正常场景、异常场景、冲突和待确认事项；引用必须指向本次有效来源。没有材料支持的判断标为建议/待确认，不假装为项目事实。
- 一次只出现一个当前确认问题；其余问题放在待办中。开发选择答案或填写补充，再明确记录产品沟通结论。模型没有代替用户确认的权限。
- 修改/移除资料、追加变更及代码版本变化后，旧分析显示为待核对。关联确认重开，未受影响确认及历史保留；不得静默抹掉用户原确认，也不得用旧草案继续发布。
- 分析调用失败保留资料、原分析及用户输入。迟到响应、并发编辑和跨项目切换不能覆盖新状态。发布沿用现有 WorkItem 创建及不确定结果重放保证。

## 验收

1. 从唯一全局入口选择工作空间，在空间内关联实际 web-idea checkout，明确选择是否纳入未提交代码。
2. 接入原始需求、实际源码、隔离环境中的知识条目、真实 DOCX/PPTX/MD；附件先保存为待 AI 读取，AI 读取后可查看内容与定位。
3. 调用 AI，验证其实际读取材料的调用记录，再展示带有效来源的正常/异常场景与冲突；只出现一个可回答问题。
4. 回填产品确认，刷新后源、分析、确认历史可恢复；A/B 工作空间切换不串数据，切回后恢复原内容。
5. 加入 Rename/JDK 等变更，关联确认转为待复核且旧结论可查，无关确认保留。
6. 覆盖解析失败、部分读取、越界路径、无权限知识、来源版本变化、并发版本冲突、模型失败与无效引用；失败不丢原记录。
7. HTTP/SQLite、UI 和模型协议模拟各自记录证据；真实模型运行单独记录，禁止将模拟输出称为真实模型验收。
