# 知识库管理员配置入口与空列表白屏

Status: implemented

## 决策与理由

2026-09-07 在现存控制平面预览的 `/agents` 点击“知识管理员验收”，页面只剩背景。浏览器错误为 `TypeError: Cannot read properties of null (reading 'join')`；`AgentConfigPanel` 初始化与取消重置均直接访问 `agent.skills.join`，Go 的空切片响应为 null。修复读模型类型与空值处理，保留空技能作为合法配置，并加入真实组件渲染防回归断言。

知识管理员沿用当前被配置 Agent 的模型和运行配置，不创建第二套配置真相。支持 `/agents?agent=<id>` 深链，角色选择加入知识库管理员；未知自定义角色保留原值。知识库设置链接直接打开该 Agent。

## 放弃了什么

不通过给每个 Agent 填入虚构技能来掩盖空值；不把用户现有 librarian Agent 转成新的系统身份；不复制模型配置表单导致两个写入口各自维护默认值。通用设置保留高级能力，日常知识输入和查看流程由知识库首页承担。

## 验收

- 空技能的管理员组件可渲染，角色可显示与保存。
- 深链直接选中目标管理员，普通切换更新地址，系统 Coordinator 不进入普通配置。
- 浏览器重新走选择、配置入口与返回知识库流程，无白屏。
